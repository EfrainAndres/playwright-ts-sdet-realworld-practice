# Dynamic Table

## Feature Name

Dynamic Table

## URL

https://practice.expandtesting.com/dynamic-table

## Feature Overview

The dynamic table page shows a Task Manager table where columns and rows change position on reload. Cell values are random. The scenario is to get the CPU value for the Chrome process and compare it with the yellow label.

## Business Value

Dynamic table testing validates that automation can locate data by row and column labels rather than brittle coordinates or fixed indexes.

## User Story

As a tester, I want to verify the Chrome CPU value in a dynamic table so that I can prove the table data matches the page summary.

## Acceptance Criteria

Scenario: Chrome CPU matches label

Given the user is on the dynamic table page
When the Task Manager table is visible
And the user finds the row where Name is Chrome
And the user reads the value under the CPU column
Then the Chrome CPU value should match the yellow label value

Scenario: Table supports changing order

Given the user reloads the dynamic table page
When the row or column order changes
Then the Chrome CPU comparison should still be valid

## Manual Test Scenarios

- Verify the Task Manager table is visible.
- Identify the Chrome row manually.
- Identify the CPU column manually.
- Compare the Chrome CPU cell value with the yellow `Chrome CPU:` label.
- Reload the page and repeat the comparison.

## Positive Scenarios

- Chrome CPU value in the table matches the yellow label.
- The comparison works after page reload.

## Negative Scenarios

- Do not rely on a fixed row index.
- Do not rely on a fixed column index.
- If Chrome row is not visible, behavior should be confirmed during implementation.

## Edge Cases

- Rows appear in a different order.
- Columns appear in a different order.
- CPU value changes format or decimal precision.

## Suggested Automation Coverage

- Locate the CPU column by header text.
- Locate the Chrome row by process name.
- Compare Chrome CPU table value with the label.
- Repeat or reload once to prove selector resilience.

## Suggested Test Data

No static test data is needed. Values are generated by the page and should be read at runtime.

## Out Of Scope

- Validating all process metrics.
- Performance testing.
- Network, memory, or disk calculations.

## Notes For Playwright Implementation Later

- Use table semantics if available.
- Avoid row and column hardcoding.
- Parse the label text carefully to extract only the CPU value.
